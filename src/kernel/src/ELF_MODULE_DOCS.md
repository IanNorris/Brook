# ELF Loader & Module System Documentation

## Overview

Brook's ELF loader handles both user-space process loading and kernel module
loading. The module system supports loadable drivers (intel_hda, virtio_input,
virtio_net, etc.) with symbol resolution against the kernel symbol table.

## ELF Loader (elf_loader.cpp)

### Key Functions

| Function | Purpose |
|----------|---------|
| `ElfValidate()` | Check ELF magic, class, endianness, machine |
| `ElfLoad()` | Load user ELF into process address space |
| `ElfLoadAt()` | Load ELF at specific address (for kernel modules) |
| `ElfFindSection()` | Find section by name in section header table |

### ELF Loading Flow (ElfLoad)
1. Validate ELF header
2. Scan PT_LOAD segments for address range
3. For PIE: compute slide from PIE_LOAD_BASE
4. Allocate user pages for each PT_LOAD segment
5. Copy file data, zero BSS
6. Set up PT_INTERP if present (dynamic linking)
7. Configure program break (heap) above load end
8. Return entry point + slide

### Known Issues (BRO-116)
- `p_vaddr + slide + b` can overflow on crafted ELF → kernel write
- Section header fields (`e_shoff`, `e_shnum`) validated for program
  headers but not section headers
- Program break calculation lacks overflow check

## Module System (module.cpp)

### Key Functions

| Function | Purpose |
|----------|---------|
| `ModuleLoad()` | Read .mod file from disk, parse, relocate, register |
| `ParseAndLoad()` | ELF section parsing, memory allocation, relocation |
| `ApplyRela()` | Apply ELF relocations (R_X86_64_64, PC32, PLT32, etc.) |
| `ResolveSymbol()` | Resolve symbol via local symtab then kernel ksymtab |
| `ModuleUnload()` | Deregister and free module pages |
| `ModuleLoadAll()` | Load all .mod files from /boot/MODULES/ |

### Module Loading Flow
1. Read entire .mod file into kernel buffer
2. Validate ELF header (magic, class, endianness, x86-64)
3. Pass 1: calculate total section size + alignment
4. Allocate module pages (`VmmAllocModulePages`)
5. Pass 2: copy section data to allocated memory
6. Find `.symtab` and `.strtab` sections
7. Apply relocations from `.rela.*` sections
8. Find and validate MODULE_MAGIC + ABI version
9. Call module's `init()` function
10. Register in loaded modules table

### Supported Relocation Types
- `R_X86_64_64` — absolute 64-bit
- `R_X86_64_PC32` — PC-relative 32-bit
- `R_X86_64_PLT32` — PLT-relative 32-bit
- `R_X86_64_32` — absolute 32-bit (truncated)
- `R_X86_64_32S` — signed 32-bit

### Known Issues (BRO-116)
- `e_shoff` not bounds-checked against buffer size
- Section data copy doesn't validate `sh_offset + sh_size <= bufferSize`
- `totalSize + 4095` page count can overflow
- `sh_link` for symtab not validated against section count
- Relocation target address not overflow-checked
- Module unload has no refcount — unloading while code executes crashes
- No file size limit — heap exhaustion possible

## Kernel Symbol Table (ksymtab.cpp)

### Design
- Two symbol sources:
  1. **Build-time exports** (`EXPORT_SYMBOL` macro) — ~1042 symbols
  2. **Address table** (generated by `gen_ksym_table`) — for stack traces
- Linear scan lookup (O(n), acceptable for module load time)

### Exported Categories
- Memory: `VmmAllocPages`, `VmmMapPage`, `PmmAllocPages`, etc.
- Sync: `KMutexLock`, `KRwLockReadLock`, `KSemaphoreWait`, etc.
- VFS: `VfsOpen`, `VfsRead`, `VfsWrite`, `VfsMount`, etc.
- Device: `DeviceRegister`, `PciConfigRead`, etc.
- Interrupt: `IdtInstallHandler`, `IoApicRegisterHandler`, etc.
- Scheduler: `SchedulerBlock`, `SchedulerUnblock`, `WakeProcess`, etc.
- Serial: `SerialPrintf`, `SerialPuts`

### Security Note
Exported functions include security-critical APIs (page allocation, interrupt
handler installation, device registration). This is inherent to the module
system design — modules run with full kernel privilege. Module loading should
be restricted to boot-time trusted paths only.
